## What this pass deliberately does not add to the backlog

Font search/preview tiles, common source icons, basic file operations, shell panel separation, existing Start pinning, window resize, taskbar previews and working browser functions already have implementation/evidence. The number and names of Windows-installed fonts/apps are not defects on a different Android device. Existing background fit/slideshow and theme saving should be reused through G19.

The recordings do not demonstrate Start pin folders, a Snap Assist second-window chooser, saved Snap-group restoration, Widgets resize/reorder menus or the internals of Windows Task Manager. Those may remain separate roadmap ideas; this review does not mislabel them as observed missing behavior. Calculator is visible primarily during launch, so the video does not establish scientific/history layout requirements. Windows loading delays, update warnings, ads, personal file contents and exact laptop specifications are not implementation targets.

OS-owned differences remain deliberate: Windows account/Store/Update/activation/NTFS/security services, PC shutdown/hibernate and keyboard/lock-screen ownership. Start's anchored Power menu already exists, but its available actions currently mean show desktop, restart Nth and Android battery settings. Any expansion must describe actual Android capabilities and permissions; Windows update/shutdown choices must not be decorative. Likewise the network/Quick Settings restricted actions should continue to route to Android when direct control is unavailable.

## Implementation order

1. **Navigation and shared Settings controls:** G01–G04, plus the visible identity correction in G29. This provides the foundation for the deeper pages.
2. **Explorer and menus:** G05–G10. Reuse the existing operations and independent tab state; add only the missing presentation/options and their necessary state.
3. **Snapping and Focus:** G11–G13. These are the clearest missing interactive behaviors demonstrated by the recordings.
4. **Settings depth:** G14–G22 and G24–G29, building useful local controls first and preserving clear Android destinations.
5. **Widgets and browser presentation:** G23 and G30, with provider-backed content only where a real source exists.

After each behavioral batch, validate the affected behavior natively and keep the established Android 11/16 shell/Nota/browser checks. Appearance-only changes need screenshot review at phone/tablet density, portrait/landscape and both themes. The initial audit marked no item complete. Use the progress table and release-specific validation notes for subsequent implementation status.
